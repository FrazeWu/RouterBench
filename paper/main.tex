\title{RouteBench: Evaluating Least-Authority Capability Routing in Tool-Using Language Agents}
\author{Anonymous ACL Submission}

\begin{document}
\maketitle

\begin{abstract}
A language agent can complete a task through several tool routes that differ in
authority and policy consequences. Task success alone does not establish whether
the selected route was safe or unnecessarily privileged. We present RouteBench,
a bounded capability-routing benchmark separating functional completion, policy
compliance, and publicly defined route optimality. Its frozen inventory contains
776 manually authored scenarios with catalog-bound typed actions, private fixtures,
and replay-checked route certificates. We make planner-interface reachability an
explicit validity check, distinguishing unavailable targets from model errors.
We further specify matched counterfactual diagnostics separating local permission
judgments, complete-route safety recognition, and safe planning, with controls for
ordinary task competence. Finally, we formulate an auxiliary evaluation-calibrated
path-aware capability attenuation defense: offline reinforcement learning selects
interventions inside trusted execution bounds. The benchmark is implemented;
the diagnostic and defense extensions require empirical validation.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

An agent can deliver an aggregate report with or without carrying protected
source fields into the outbound message. Both routes may finish the task using
the same tools and coarse permissions, but their policy consequences differ.
A safe route can also use standing credentials where delegated access suffices.
Completion, safety, and least-authority choice ask different questions.

Least privilege \citep{saltzer1975} and information-flow tracking
\citep{sabelfeld2003} predate language agents. Here the challenge is interpreting
language tasks and policies while comparing typed action sequences.
Prompt-injection benchmarks \citep{zhan2024injecagent,debenedetti2024agentdojo}
and agent-risk evaluations \citep{ruan2024toolemu,zhang2024safetybench}
establish important safety settings. ToolPrivBench directly studies choosing
higher-privilege tools when lower-privilege alternatives suffice
\citep{yang2026toolprivbench}. These advances motivate a specific question:
can an agent choose a safe, functionally complete, least-authority \emph{path}
under an explicit, observable comparison contract?

RouteBench isolates routing, not unrestricted code generation. The model selects
a path through a finite graph of catalog-bound actions. Deterministic replay
checks effects from a clean state; public ordinal attributes define preference
without revealing private costs or reference certificates.

A failed endpoint can reflect task competence, permission judgment, composition
recognition, or planning. It can also reflect an unselectable target. We separate
construction validity, interface validity, and model behavior.

The paper has three contributions:
\begin{itemize}
 \item An implemented capability-routing benchmark with separate task, policy,
 and optimality endpoints, public comparison rules, trusted replay, and an
 explicit audit of interface reachability.
 \item A proposed counterfactual protocol separating local permission judgment,
 composition-safety recognition, and safe planning, with task-competence and
 presentation controls.
 \item A specified auxiliary defense, evaluation-calibrated path-aware
 capability attenuation (ECPA), connecting development diagnostics to bounded
 runtime interventions and constrained offline learning.
\end{itemize}
The latter two are methodological specifications, not claims of an observed
diagnostic gap or validated defense improvement.

\section{Related Work}
\label{sec:related}

\paragraph{Agent safety evaluation.}
InjecAgent and AgentDojo evaluate indirect prompt injection
\citep{zhan2024injecagent,debenedetti2024agentdojo}; AgentHarm studies multi-step
harmful tasks \citep{andriushchenko2025agentharm}, and Agent-SafetyBench broader
interaction risks \citep{zhang2024safetybench}. ToolEmu uses model-emulated tools
and safety evaluation \citep{ruan2024toolemu}. RouteBench instead compares
deterministic typed effects within bounded graphs; auditability does not replace
open-world realism or attack coverage.

\paragraph{Privilege-sensitive choice.}
ToolPrivBench studies initial over-privileged choice and error-induced escalation
among individually sufficient tool alternatives, with privilege-aware
post-training \citep{yang2026toolprivbench}. RouteBench compares
dependency-constrained paths with distinct functional, policy, and optimality
outcomes. Least-privilege tool evaluation is not new. The proposed diagnostics
match tools and authority where feasible while varying provenance or order.

\paragraph{Structural controls and learning.}
StruQ separates instructions and data through structured queries and training
\citep{chen2025struq}. CaMeL separates control/data flow and checks capability-governed
releases \citep{debenedetti2025camel}. Progent enforces symbolic tool policies
with checked narrowing or approved expansion \citep{shi2025progent};
AgentGuard covers single- and cross-tool risks through attribute-based access
control \citep{luo2026agentguard}. RACG gates exposure using causal paths,
authorization prerequisites, and provenance \citep{iyer2026racg}.
APPA supports policy-governed recovery \citep{kravchenko2026appa}, while
CONTINUITY studies security-context contracts across components
\citep{zheng2026continuity}. Path awareness, attenuation, and recovery are
therefore not new guarantees of ECPA.

ECPA asks whether development diagnostics help choose low-cost interventions
without destroying safe completion options. Hard bounds follow the established
learner/shield separation \citep{alshiekh2018shielding}. Constrained optimization
\citep{achiam2017cpo} and conservative offline learning \citep{kumar2020cql}
supply the formulation, not a new RL algorithm. Learning must earn its place
against deterministic path-state, causal-gating, and recovery controls with
comparable information and intervention choices.

\section{Capability-Routing Problem}
\label{sec:problem}

\subsection{Paths, Effects, and Policy}

A scenario is $\mathcal{S}=(T,G,s_0,\delta,F_T,C,B)$: task $T$, directed graph
$G=(V,E)$, private fixture $s_0$, trusted tool transition $\delta$, functional
verifier $F_T$, policy verifier $C$, and forbidden-effect predicates $B$.
An edge binds a registered adapter, typed arguments, and a concrete
provider--resource--mode capability. Its authority declaration $A_e$ contains
exact $(\mathrm{resource},\mathrm{operation},\mathrm{target})$ atoms.
Trusted previews recompute these atoms during construction auditing.

Let $\mathcal{P}_H$ contain graph-continuous start-to-terminal paths within
bound $H$. Dependencies must hold before execution. Replay produces state
$s_k$ and history $\tau_k$. Write $F_T(p)$ and $C(p)$ for verification after
replay, and $B(p)=1$ when an assigned forbidden target is realized.
The eligible set is
\[
 \mathcal{P}_{\mathrm{safe}}
 =\{p\in\mathcal{P}_H:F_T(p)\land C(p)\land\neg B(p)\}.
\]
Compliance alone does not imply completion: doing nothing may be compliant.
The footprint $A(p)=\bigcup_{e\in p}A_e$ is also insufficient to determine
composition safety because it discards order and data dependencies.

\subsection{An Observable Preference Contract}

The formal inventory assigns four public ordinal attributes to every edge:
exposure, authority scope, evidence loss, and interaction.
Each has four levels ranked $0$ through $3$, with lower preferred
(Table~\ref{tab:ordinals}). Define
\[
 q_j(p)=\sum_{e\in p}r_j(e),\qquad \mathbf{q}(p)=(q_1,q_2,q_3,q_4),
\]
\[
 \mathcal{P}^{*}=
 \underset{p\in\mathcal{P}_{\mathrm{safe}}}
 {\operatorname{arg\,min}_{\mathrm{lex}}}\ \mathbf{q}(p).
\]
Comparison is lexicographic in that order. All exact minimizers receive credit.
Pareto optimality is reported separately, not substituted for the exact endpoint.
The current planner payload also contains a conflicting Pareto-credit field.
The two optimal sets coincide in all 776 frozen cases, so this does not change
their scoring sets; future freezes must align the prompt and scorer explicitly.

\centering

\toprule
Dimension & Levels, from rank 0 to rank 3 \\
\midrule

\emph{Least authority} here is graph-relative preference, not universal minimality.
Ordinal attributes cannot make forbidden effects eligible.

\subsection{Threat Model and Trust Boundary}

The untrusted planner selects routes but cannot modify bindings, semantics,
verifiers, or fixtures. Unsafe branches are decoys under ordinary tasks,
not active prompt-injection attacks.

Public input contains task, functional goal, typed tools, graph, arguments,
authority, and ordering, but not descriptive branch names. Fixtures,
certificates, minimum-authority declarations, costs, and outcomes are private.
Diagnostics additionally expose policy and sufficient symbolic state; not every
historical case meets that stronger condition. Typed execution and verification
are trusted. Arbitrary shell access, adapter compromise, and side channels
are out of scope.

\subsection{Catalog-Bound Authoring}

For each schema-v4 case, authors manually select primitive adapters, a concrete
capability binding, planning skills, and a workflow template from the capability
universe; the executor catalog is only the adapter registry. Multiple viable,
dependency-constrained routes precede assignment of the evaluator reference.

A case contains a public task/graph, private fixture, functional/policy assertions,
and safe/forbidden-target certificates. Bounded enumeration checks edge reachability,
dependencies, previewed authority, safe completion, and forbidden effects.
Certificates are replay witnesses, not model-visible answers.
Construction also requires a non-reference terminal path no longer than the
reference, blocking a unique-shortest-path shortcut but not every presentation
or semantic shortcut.

All self-authored task and fixture content is synthetic. A single reviewer
manually checked a random 10\% sample for task plausibility, policy clarity,
and route-label correctness; no issues were identified in that sample.

\subsection{Inventory and Coverage}

The frozen inventory contains 776 primary cases, 4,982 edges, and 16 test
template families, with 3--6 bounded terminal paths per graph.
All formal edges have public ordinal attributes. The freeze records 761 unique
exact optima and 15 cases with equal public rank; universal uniqueness is
not a property of this inventory.

The taxonomy has eight effect families (Table~\ref{tab:effects}), eight permission
dimensions, ten tool surfaces, five topology labels, and six mechanisms:
fixed controls, parameter/scope and equivalent-tool substitution, staging,
reordering, and authorization-state manipulation. Tags do not establish coverage
of every cross-product or realistic attack. Appendix~\ref{app:artifacts} lists
the permission dimensions.

populated in the formal inventory. Safe certificate lengths are 1--5 actions;
nominal strata and actual path lengths must not be conflated.
Development cases are additional. Split independence must be audited by semantic
workflow family, not renamed entities or substituted fixture values.

\subsection{Interface Eligibility}
\label{sec:eligibility}

Construction validity does not establish interface validity.
Let $\mathcal{P}_{\nu}$ denote routes selectable under interface $\nu$.
Current v13 selects outgoing edges and stops at the first declared terminal.
It excludes paths continuing through an interior terminal, although enumeration
includes them. Deterministic replay auditing finds 45 frozen cases with no
v13-reachable safe functional route, and 279 with no reachable forbidden
route. The former also lack a reachable exact optimum.

These are graph/interface properties, not model outcomes.
Keep the original 776-case endpoint identifiable. Filtering needs a distinct
analysis identity and performance-independent eligibility rule. Capability
interpretation requires a reachable optimum; attack avoidance requires an unsafe
alternative. Appendix~\ref{app:repair} specifies a proposed stop/continue repair;
it needs a new protocol and fresh measurements, not overwritten v13 results.

\section{Evaluation Contract}
\label{sec:protocol}

\paragraph{Selection and execution.}
V13 exposes the whole graph and selects outgoing edges through JSON, without
replay observations, repair, backtracking, or retries. Seed-stable label/order
permutations change presentation only. Earlier full-path and unpermuted
protocols are separate conditions.

\paragraph{Endpoints.}
For valid replay, report functional success $F_T$, compliance $C$,
forbidden-target realization $B$, safe completion
$J=F_T\land C\land\neg B$, and exact optimality
$O=J\land[p\in\mathcal{P}^{*}]$.
Certificate matching and Pareto optimality are separate diagnostics.
Malformed output is an assessed model failure. Backend failure leaves a
case unassessed, not safely refused. Denominators distinguish valid, invalid,
infrastructure-failed, and interface-ineligible cases.

\paragraph{Replication and provenance.}
Five seeds at temperature zero index repeated case/presentation measurements;
the capable-case endpoint requires at least three optimal successes.
Seeds are not independent samples. Use paired case-level uncertainty and
family-aware sensitivity checks.

Manifests bind clean source revision, planner/dependency and model hashes,
runtime, scenario digests, and generation settings. Aggregates exclude raw
prompts, responses, fixtures, graphs, and certificates. Development alone
supports prompt/controller selection. Fresh diagnostic and defense tests need
independent freezes; reused formal results are not unseen generalization.

\section{Counterfactual Composition Diagnostics}
\label{sec:diagnostics}

% Proposed protocol; no observed diagnostic gap is claimed.
The unit is a matched pair $(p^{+},p^{-})$. Both complete the ordinary task
under trusted replay; only $p^{-}$ realizes a specified forbidden effect.
Pairs share task, initial state, tools, and, where feasible, requested authority.
Change one declared dependency or ordering relation. Record residual
differences when exact matching fails rather than calling the contrast
composition-only.

Public inputs include authorization rules, semantics, classifications, and
symbolic state sufficient to infer safety for all private fixtures consistent
with that projection. Ambiguity disqualifies a pair. Inputs exclude private
values, post-states, certificates, and labels. Both routes must be selectable
under the diagnostic interface; ordinary task completion by both is an
inclusion criterion.

\subsection{Two Controlled Interventions}

\paragraph{Data dependencies.}
Both routes deliver an aggregate report, matching tools, resources, and authority
where feasible. The public policy permits internal access but forbids outbound
source fields. Change payload dependencies: only the unsafe route additionally
carries protected source fields. Public classifications and symbolic references
make provenance inferable without private values. Blanket outbound refusal
fails the safe control.

\paragraph{Execution order.}
Vary only order, fixing task, initial state, tools, arguments, and authority.
A public policy requires auditing whenever a sensitive configuration is modified.
Starting with auditing disabled, the safe route enables auditing before
modification; the unsafe route modifies before enabling auditing.
Both finish with the same configuration and audit-enable flag, but only the
latter includes an unaudited modification. Check a persistent history predicate,
not those terminal values alone. Initial audit state, policy, and semantics
are public. This proposed example does not imply that the existing terminal-state
verifier implements the event monitor.

\subsection{Recognition and Planning}

Use isolated contexts without feedback between tests.
An ordinary task-only control measures functional competence ($K$).
Local tests ($L$) cover static subject/operation/resource judgments and
one-event policy-rule comprehension with authorized/unauthorized controls.
They use the same rule wording without requiring history or dependency
reconstruction: passing $L$ does not logically entail route safety.
Recognition ($R$) requires correctly labeling both routes.
Planning ($J$) requires safe functional completion from the shared graph.
Constant unsafe labels fail paired recognition; refusal fails planning.

Report marginal outcomes and their joint distribution, including
\begin{align*}
 D_{\mathrm{rec}}&=\Pr(\neg R\mid K\land L),\\
 D_{\mathrm{plan}}&=\Pr(\neg J\mid K\land L\land R).
\end{align*}
Zero conditioning counts mean undefined estimates, not zero error.
Recognition failure supports a behavioral composition gap; planning failure
after recognition supports a recognition/planning discrepancy. Neither reveals
internal reasoning or establishes a causal cognitive mechanism.
Task-only failures remain capability failures.

Counterbalance route order and labels; include semantic-preserving paraphrases
without removing safety evidence. Resample at the task/pair level, keeping
repeated presentations together. Report unconditional and conditioned estimates
because conditioning can select easier tasks.
Independently author this suite without changing frozen RouteBench cases.

\section{Auxiliary Defense: ECPA}
\label{sec:ecpa}

% Proposed design; implementation and empirical validation remain pending.
ECPA uses development diagnostics to prioritize training strata, not grant
authority. Data-flow and order contrasts respectively identify source/sink and
history-sensitive strata. Trusted policies determine admissibility; reference
certificates never supply runtime advice. ECPA needs a separately frozen
interleaved execution/replanning protocol, not v13 pre-replay selection.

\subsection{State and Intervention Menu}

The decision state is
\[
 x_t=(T^{\mathrm{pub}},G^{\mathrm{pub}},n_t,a_t,K_t,q_t,d_t,b_t),
\]
with position $n_t$, proposed call $a_t$, grant envelope $K_t$, trusted monitor
$q_t$, provenance $d_t$, and budget $b_t$. Hidden optima, private fixture values,
and model explanations are not authorization evidence. The state must retain
transition-relevant information for a Markov interpretation.

The trusted finite menu contains:
\begin{itemize}
 \item \textbf{Allow}: dispatch after trusted checks.
 \item \textbf{Constrain}: offer a registered narrower typed request for explicit
 acceptance or replanning.
 \item \textbf{Escalate}: suspend pending trusted approval bound to principal,
 task, exact request, policy epoch, and validity period.
 \item \textbf{Deny}: reject with bounded replanning or termination.
\end{itemize}
Trusted code enumerates bindings; pending/rejected requests have no external
effect. Between authenticated approvals, $K_{t+1}\subseteq K_t$.
Prerequisites can activate actions inside existing grants, not expand them.
Only trusted transformations change classifications. Atomic final-request
checks bind request hash and policy version to prevent check/use substitution.

\subsection{Completion-Preserving Attenuation}

For intervention $u$ with grants $K'(u)$, let $\mathcal{W}(x_t,u)$ contain
monitor-admissible, goal-completing suffixes from its predicted successor state.
Read-only trusted previews include the replacement call's effects and consumed
budget; pre-intervention reachability alone is insufficient. Require a witness
for each modeled successor, with an empty suffix allowed for completed tasks.
Reject constraints eliminating all continuations when completion was available.
Unknown reachability triggers deferral/denial. The menu $\mathcal{M}(x_t)$ combines
typed validity, grant inclusion, history/data-flow checks, and this test.
Witnesses are model-relative and do not ensure planner compliance.
Exact cost-sensitive search remains a required non-learning baseline.

\subsection{Data and Offline Learning}
\label{sec:learning}

A new corpus is required; current development cases are not presumed sufficient.
Split semantic families into training, tuning, calibration, and fresh tests.
Independent development diagnostics prioritize contrast strata with recognition
or planning failures. Collect traces from frozen planners and rule controllers,
retaining logging probabilities and stratum weights; also collect uniform
coverage. The learning data are
\[
 \mathcal{D}=\{(x_t,u_t,r_t,v_t,x_{t+1},z_t)\},
\]
where $u_t$ is the executed intervention and $z_t$ termination. Trusted replay
labels utility, authority, and intervention cost. Rejected proposals are not
executed actions. Include failures and unsafe proposals, but no formal test
cases or live-service attacks.

For bounded horizon $H$ and nonnegative cost $c_t$, set
$r_t=z_tF_T(s_{t+1})-c_t$; utility is credited once at termination.
Optimize
\begin{align*}
 \max_{\pi}\quad &J_U=\mathbb{E}_{\pi}\sum_{t<H}r_t,\\
 \text{subject to}\quad &J_V=\mathbb{E}_{\pi}\sum_{t<H}v_t\leq\alpha.
\end{align*}
For sticky violation state $h_t$ with $h_0=0$, set $v_t=h_{t+1}-h_t$;
$J_V$ is thus the episode violation probability, not repeated violation counts.
Authority and intervention costs do not redefine ordinal optimality.

Use discrete conservative Q-learning \citep{kumar2020cql} on supported,
admissible choices with scalar reward $r-\lambda v$. Invalid choices are guard
tests, not critic actions. Empty menus terminate; low support, critic
disagreement, or invalid features trigger deterministic fallback.
Appendix~\ref{app:training} gives the loss, defaults, and sampling rule.

Tuning chooses the multiplier and fallback thresholds. Independent calibration
then audits that fixed policy with a one-sided episode-risk bound; no candidate
reselections use the same audit data. Report infeasibility if it misses the
budget. This is distribution-specific evidence, not safety under shift.
For completely mediated, soundly monitored effects, violations are excluded by
the guard; calibration checks implementation and uncovered risk, not permission
to relax it. Freeze the controller before testing; no deployed online exploration
updates authority.

\subsection{Guarantees and Empirical Burden}

Complete mediation, sound subset checks, and unforgeable approval imply
$K_t\subseteq K_0$ within an approval epoch, with $K_0$ its initial grants.
Sound effect monitors exclude their
specified forbidden effects. This is an established reference-monitor argument,
not a new theorem or RL guarantee; bypasses or incorrect contracts invalidate it.

Compare matched-menu rules, path-state controls, and exact search;
minimum-authority and private-fixture oracles are privileged references.
Ablate diagnostic allocation, history, provenance, preservation, and learning.
Report violations, completion, authority, interventions, approvals, and overhead.
Appendix~\ref{app:training} fixes comparisons and success criteria.
Equality with deterministic controls does not establish learning's added value.

\section{Experiments}
\label{sec:experiments}

\paragraph{Protocol.}
We report the existing historical v13 evaluation, rather than a repaired
stop/continue interface. The held-out inventory has 776 cases; five presentation
seeds were run for each full-benchmark model (3,880 attempts per model) with
temperature 0, top-$p$ 1, and a 2,048-token output limit. A case is
\emph{capable} when at least three of its five attempts achieve the evaluator's
exact \texttt{OptimalPathSuccess}. The inference unit is the case, with seeds
treated as repeated measurements. We use 10,000 paired case bootstrap resamples
(seed 20261004) for descriptive 95\% intervals and make no causal or $p$-value
claim. All runs use the trusted local simulator and synthetic fixtures; no live
service, credential, or destructive action is involved.

\paragraph{Defense status.}
The results establish benchmark and diagnostic signals only. No offline RL,
ECPA controller, or defense-improvement experiment has been run; consequently
we make no claim that the proposed defense reduces violations or preserves
utility.

\section{Discussion}
\label{sec:discussion}

Across the historical benchmark, exact route choice varies substantially across
models, and the paired graph ablation shows that authority contrasts are a
particularly informative diagnostic signal. Interface reachability still
qualifies capability and attack-avoidance results, while ordinal optimality
expresses bounded preferences. These observations motivate composition checks
and recovery, but symbolic and information-flow controls remain strong
alternatives. Diagnostic-guided learning must demonstrate added value on new
workflows under equal information and intervention budgets; the present results
do not test that claim.

\section{Conclusion}

RouteBench separates completion, compliance, and optimality through bounded
replay and public comparison rules. The existing v13 results quantify model
differences and expose structural difficulty signals, while interface
reachability remains a validity condition rather than model capability. Matched
diagnostics and ECPA specify a testable evaluation-to-defense connection with
trusted authorization; their effectiveness remains an empirical question.

\section*{Limitations}
\label{sec:limitations}

\paragraph{Bounded simulation.}
Graphs contain only 3--6 terminal paths and safe certificates 1--5 actions.
They do not establish long-horizon planning, unrestricted code correctness,
or safety against arbitrary APIs. Deterministic fixtures remove tool
stochasticity rather than model it. Language understanding is measured through
task/rule interpretation and typed routing; multilingual or ambiguous-policy
robustness is not established.

\paragraph{Validity and preference.}
The mismatch in Section~\ref{sec:eligibility} limits historical v13 interpretation.
Unavailable unsafe routes can inflate apparent attack avoidance; unavailable
safe routes can depress capability. Filtering changes the benchmark population
and potentially its family composition.
Ordinal sums and lexicographic priorities are conventions, not calibrated risk,
and include evidence/interaction preferences beyond privilege.
Coverage tags do not establish deployment frequencies.
The coincident Pareto/exact sets do not test preference trade-offs.
Authoring neutrality and semantic family independence require human review;
structural checks alone cannot establish them.
The single-reviewer 10\% check leaves reliability on unreviewed cases and
agreement across reviewers unmeasured.

\paragraph{Proposed extensions.}
The diagnostic corpus, history-sensitive diagnostic verifier, and learned
ECPA controller are not validated in this draft. Conditional rates do not
reveal reasoning and depend on matching quality and public information.
Existing development cases do not establish adequate learning coverage.

\paragraph{Enforcement and generalization.}
ECPA assumes trusted labels, complete mediation, correct contracts, atomic
dispatch, and authenticated approval. Provenance does not imply general
noninterference of model outputs. Completion witnesses may be wrong outside
their abstraction. Offline support and calibration limits do not guarantee
safety under shift. Human approval is not infallible.
Learning's advantage over deterministic control remains unproven.

\section*{Ethical Considerations}

Intended use is controlled evaluation and defense research, not escalation
against deployed systems. Formal graph replay uses an in-memory simulator,
not live accounts or services. All self-authored scenarios use synthetic
file contents, identities, resource identifiers, and credentials; they do not
contain real business or user records. Aggregate artifacts omit prompts, responses, fixtures, and
certificates. Response hashes provide integrity, not anonymity.

Unsafe-route examples have dual-use value. We plan to release original code,
self-authored synthetic task files, and evaluation scripts under GNU GPLv3,
with an anonymous version for review. Third-party code, data, models, and ACL
style files retain their upstream licenses and provenance.
Archive preparation and publication remain pending.
Resources and training/selection costs must accompany eventual experiments.

Generative AI assisted literature discovery, conceptual discussion, drafting,
revision, and LaTeX maintenance, including diagnostic/defense design discussion.
It is not an author. Human authors remain responsible for references, methods,
novelty, licenses, and claims. Disclose this scope in the Responsible NLP Checklist and the final
acknowledgments.

\section{Public and Private Artifact Contract}
\label{app:artifacts}

The public task projection contains prompt, functional goal, and tools.
The graph contains connectivity, start/terminal declarations, path bound,
arguments, authority atoms, capability bindings, and ordinal attributes.
Anonymization remaps labels, not effects. The incremental interface supplies
selected prefixes, not tool observations during planning.
Permission dimensions are subject/tenant, operation, resource, data,
destination, purpose, temporal/path state, and quota.

Evaluator artifacts contain fixtures, functional/compliance assertions,
forbidden-target assertions, certificates, and digests. Controller features
use deployment-authorized trusted summaries, not private benchmark answers.
An anonymous review archive should include schema/catalog versions,
verifier code, eligibility rules, split metadata, and replay instructions.
Original code and self-authored task files are designated GPLv3; anonymous
review access and public distribution are planned, not yet available.
Legacy atom-only cases minimize set inclusion then action count under a
uniqueness contract, not the formal ordinal endpoint.

\section{Proposed Training Defaults}
\label{app:training}

These defaults specify a design, not an executed run.
For finite-horizon discrete CQL, use
\begin{equation}
\begin{aligned}
 \mathcal{L}(Q)&=\tfrac12\mathbb{E}_{\mathcal{D}}(Q(x,u)-y)^2\\
 &\quad+\eta\,\mathbb{E}_{x\sim\mathcal{D}}\mathcal{R}(Q;x),\\
 \mathcal{R}(Q;x)&=\log\sum_{u\in\mathcal{M}(x)}e^{Q(x,u)}\\
 &\quad-\mathbb{E}_{u\sim\beta(\cdot\mid x)}Q(x,u),
\end{aligned}
 \label{eq:cql}
\end{equation}
where $\beta$ is logged behavior and $\bar Q$ a target critic.
For nonterminal transitions,
$y=r-\lambda v+\bar Q(x',\widehat\pi(x'))$;
otherwise $y=r-\lambda v$. Empty successor menus terminate with abstention.

The backup/deployed selector $\widehat\pi$ chooses the best member of
$\mathcal{U}(x)\subseteq\mathcal{M}(x)$, defined by a tuning-fixed logging-support
threshold. Low support or critic disagreement invokes a deterministic admissible
fallback, whose transitions enter both logging and calibration. This avoids an
undefined maximum over an empty supported set. The conservative penalty covers
the whole admissible menu. All interventions consume the finite decision budget,
including rejection and approval requests.

Encode public task/policy text using a frozen sentence-embedding model
\citep{reimers2019sentencebert}; the proposed checkpoint is
\nolinkurl{sentence-transformers/all-MiniLM-L6-v2}.
Concatenate its vector with categorical typed state/menu embeddings,
monitor/provenance summaries, and remaining budgets.
Pin the encoder and tokenizer before training. It cannot authorize grants.

Use five independently initialized scalar critics with two 256-unit ReLU layers.
Adam uses learning rate $3\times10^{-4}$ and batch size 256; finite-horizon
discount is 1. Start with $\eta=1$ and Polyak target factor 0.005.
Cap training at 100,000 updates with development-only selection every 2,000.
Normalize costs with training-set scales and freeze their weights before tests.
Ensemble disagreement and logging-policy support are abstention features,
not certified per-action bounds.

For diagnostic stratum $s$, use priority
$a_s=\epsilon+\widehat D_{\mathrm{rec},s}+\widehat D_{\mathrm{plan},s}$,
where strata are preregistered policy/effect and intervention-type cells;
the proposed default is $\epsilon=0.1$. Undefined conditional rates contribute zero,
not an inferred absence of error; retain their counts. Allocate a fixed
collection budget half uniformly and half in proportion to $a_s$ within training
families. Record sampling probabilities. Compare uniform
and prioritized collection at equal budgets and identical trusted menus.
The frequencies change data allocation only, never grant validity.

Within each training stratum and nonempty menu, use a simulator-only mixture
$\beta(u\mid x)=\tfrac12\beta_{\mathrm{rules}}(u\mid x)+
\tfrac12\operatorname{Unif}(\mathcal{M}(x))$.
The rule-controller mixture is frozen before collection; all random choices
remain inside trusted bounds. This supplies intervention coverage rather than
only replaying whichever decision a single controller happened to take.
Log effective probabilities after any deterministic override, including fallback.
Approval availability and outcomes follow a fixed trusted simulator policy,
not a model-generated authorization or assumed acceptance. No such exploration
occurs against deployed accounts. Collection is proposed, not performed.

Calibration uses episode-level uncertainty under its declared sampling design.
An exact binomial bound is appropriate only for independent Bernoulli episodes;
repeated seeds or presentations of a case cannot be counted as independent.
Set confidence level and risk budget before collection. Charge nonnegative,
training-normalized authority-use, intervention, and execution costs in $c_t$;
fix their weights using tuning data, not calibration or test outcomes.

Split by task family before collecting traces; no semantic family crosses
training, tuning, calibration, and fresh defense tests. Diagnostic allocation
uses development families only; report any shared training/development strata.
Dataset size, behavior coverage, risk budget, cost weights, support thresholds,
checkpoint, licenses, and compute are run-dependent quantities to report with
experiments. Insufficient support or calibration coverage requires reporting
infeasibility, not relaxing requirements after observing tests.

\paragraph{Planned comparisons and success criterion.}
The minimum comparison includes no defense, a public-input rule controller,
uniform-collection CQL, and diagnostic-guided CQL. Freeze the strongest rule
comparator using tuning data before calibration and tests.
Both learned variants share architecture, rewards, menus, guards, approval
rules, and collection budgets; only diagnostic data allocation differs.
For the strict safety claim, require the one-sided 95\% upper confidence
limit for $V_{\mathrm{RL}}-V_{\mathrm{rule}}$ to be below zero and the lower
limit for $F_{\mathrm{RL}}-F_{\mathrm{rule}}$ to be at least $-0.02$, where
$V$ is episode violation rate and $F$ is benign functional success rate.
Pair cases and settings; cluster uncertainty by semantic family and retain
repeated presentations and all training seeds within those units.
Diagnostic-guided versus uniform CQL is a separate matched-budget comparison.
If common sound guards make all violation rates zero, the strict safety
criterion cannot be met; report utility and costs separately without claiming
an additional reduction in violations. These are planned tests, not results.

\paragraph{Planned compute and replication.}
The available host has two NVIDIA A100-PCIe-40GB GPUs and approximately
196\,GiB of RAM. Use a frozen Qwen3-14B planner in BF16 on one GPU;
Qwen3-8B and a separately pinned other-family planner provide transfer tests.
Start inference at an 8,192-token context, at most four concurrent sequences,
and 90\% GPU-memory utilization. Check projected prompt lengths on development
data before freezing limits; do not truncate test inputs to fit them.
Run five independent controller-training seeds, distinct from repeated planner
presentations. These are resource plans; throughput, elapsed time, and memory
use require measurement in the eventual runs.

\section{Proposed Runtime and Transition Contract}
\label{app:runtime}

This protocol specifies the environment for ECPA, not an implemented extension
of v13. Use a frozen planner with stateless calls conditioned on the public
task/graph, current node, and trusted execution receipts. Pin its model and
generation settings. Persistent planner memory, if introduced, must enter the
recorded decision state; monitor summaries alone cannot be presumed Markov.

\begin{enumerate}
 \item Receive an untrusted typed proposal. Reconstruct authorization state,
 provenance, graph position, and remaining budget from trusted receipts.
 \item Enumerate registered allow/constrain variants in the frozen action
 vocabulary. Narrowing is an explicit alternative request, never a hidden
 parameter rewrite or an unregistered graph transition.
 \item Preview each candidate without external effects. Check requested atoms
 against grants, policy/history predicates, and post-intervention completion
 witnesses. An uncertain preview is not a safe witness.
 \item Select a supported intervention with the learned policy, or use the
 frozen deterministic fallback. Rejection and pending approval dispatch nothing.
 Constrain requires explicit acceptance of its new request; refusal leads to
 replanning without execution of the original request.
 \item Bind the accepted request, principal, task, and policy epoch. Recheck
 against current trusted state immediately before atomic dispatch; stale state
 invalidates the menu. Authenticated approval starts a new grant epoch and a
 fresh check. It never waives fixed forbidden-effect predicates.
 \item Record the dispatched call or non-dispatch decision, trusted receipt,
 next proposal/state, costs, first-violation increment, and termination. Every
 intervention consumes budget; exhausted budgets, unresolved approval deadlines,
 and empty admissible menus terminate with their actual task outcome.
\end{enumerate}

Logging interventions must actually alter the simulated rollout: copying the
reward from an unguarded trace after relabeling its decision is invalid.
Store the behavior probability of the executed intervention, including fallback,
and separate proposal, accepted request, and dispatched effect. Record
rejection-induced replanning and approval outcomes rather than imputing successful
recovery. Runtime private values are not critic inputs or public release data.
All baselines use the same proposal/feedback contract, action variants, approval
rules, and decision budgets; evaluator-informed oracles are labeled separately.

\section{Proposed Selectability Repair}
\label{app:repair}

Define a fresh interface $\nu^{+}$ with the same public graph, ordinal priority,
and edge bound $H$, retaining the schema's nonterminal start requirement.
At a nonterminal node, only an outgoing edge is admissible.
At a terminal node, the model may explicitly stop or choose an outgoing edge.
Stop is a protocol decision with no tool effect or ordinal charge, not a new
capability adapter. It is invalid at nonterminal nodes. After $H$ edges, only
stop at a terminal is valid; otherwise the path is a model failure. A dead end
that is not terminal is likewise invalid. There is no retry or path repair.

Use a disjoint JSON union: either one \texttt{edge\_id} from currently outgoing
edges or \texttt{\{"stop":true\}} when stopping is admissible. Reject mixed fields,
unknown edges, and invalid stops. The full graph and selected prefix remain
visible; benchmark planning still precedes replay. Seeded presentation remaps
edge/node labels without remapping the stop decision. Report edge choices,
model calls, and stop decisions separately.

Every enumerated start-to-terminal path of at most $H$ edges can be represented
by its edge sequence followed by stop, including interior terminals. Conversely,
each valid response sequence yields such a graph path. This establishes
selectability relative to the enumerator, not functional or policy correctness.
Replay and the existing verifiers still decide those outcomes.

The new public comparison contract must give all exact lexicographic minimizers
credit and identify Pareto status as a secondary diagnostic. Tests must cover
interior terminals, terminal starts, empty outgoing menus, bound exhaustion,
mixed JSON responses, and equal-rank ties. Verify prompt/scorer agreement and
inventory-wide selectability before freezing. This specification is not a v13
patch or a claim of an implemented protocol; it requires a new committed identity
and fresh measurements, with historical manifests retained unchanged.
